## 2. SWOT Summary

**Strengths (keep):** server storage pipeline (`save_media` SHA-256 dedupe + tmp/replace);
parameterized SQL everywhere in `database.py`; `TransferManager` state machine + 250MB
space margin; desktop `contextIsolation:true` + narrow contextBridge preload; android
streaming upload with temp file + sha256 pre-dedupe; WorkManager unique-work REPLACE policy.

**Weaknesses (-> defects, see Sec 3):** path validation gaps (archive/zip target joins,
absolute-path join, android download filename), auth token exposure (`/pairing/info`,
`get_all_devices`), cleartext transport end-to-end on android, non-atomic writes in 3 spots,
unbounded in-memory reads/zips, no route auth documentation, WS reconnect storm on android.

**Opportunities:** EncryptedSharedPreferences + network-security-config pair one change;
server-side `total_size` enforcement one check; `busy_timeout` + init-once-at-startup one
move; centralize android Bearer header in `PhotoSyncApiClient`.

**Threats:** LAN-adjacent attacker model (any device on the Wi-Fi) makes S1 auth/exposure
items blast radius "arbitrary client on LAN"; S0 open-folder abuse = host code execution
when paired with unauthenticated chunked upload; CORS `*`+credentials makes it reachable
from any website in a browser.
