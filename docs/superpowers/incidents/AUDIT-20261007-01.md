## 3. Confirmed Findings

### F-01 — Arbitrary file read via unauthenticated path traversal (S1, TD-005)

`server/main.py:356-361`. The route declares `{relative_path:path}`, an unconstrained
multi-segment parameter, and joins it straight onto the backup root:

```python
file_path = get_backup_dir() / relative_path   # no sanitize_filename, no resolve(), no containment check
```

Probe F-01 confirmed the leak by constructing a sibling file outside the backup root:

```
-> CONFIRMED: join resolves to ...\Backups\..\SECRET_OUTSIDE_BACKUPS.txt outside backup root;
   bytes readable = 'TOP-SECRET-HOST-FILE-CONTENT'
```

No `Authorization` header is required. Any device on the LAN can read arbitrary files
the server process can read, constrained only by `os.path.is_file`. This is the single
highest-value finding in the audit. Fix: resolve, then assert containment before
returning — do not sanitize the string, since a legitimate nested relative path must
still work.

### F-03 — Non-atomic Quick-Drop write (S2, TD-006)

`server/storage.py:139`. `save_quick_drop` opens the **final** path for writing. Compare
`save_media` at `storage.py:102-106`, which correctly stages to `.tmp_{pid}` and calls
`.replace()`. A crash or `ENOSPC` mid-write leaves a truncated file at the advertised
path, and `list_pending_drops` will hand it to a phone as if complete.

Probe: `tmp staging files present=[]` — confirms no staging layer exists.

### F-04 — Non-atomic folder-transfer write (S2, TD-007)

`server/transfer_manager.py:248`. Same defect class in `save_folder_upload`. Because the
destination is a directory tree, a partial transfer is worse than a partial file:
`list_transfers` enumerates the folder and reports whatever landed, with no completion
marker to distinguish a finished tree from a half-copied one.

Probe confirmed: `final path ...\Transfers\FolderX\f.txt written directly, no tmp+replace`.

### F-05 — PIN brute force (S1, TD-001, pre-existing)

`server/auth.py:31-47`. `verify_pin_and_pair` compares with `secrets.compare_digest`
(good — constant-time) but tracks no attempt count and applies no backoff. A 6-digit PIN
over a 600s window is enumerable by any LAN host. This is the already-registered TD-001,
now backed by an executable guard (`test_pairing_locks_out_after_repeated_failures`).

### F-06 — 18 routes outside the auth allowlist (S1, TD-008)

`audit_cluster_a.py` classifies every route as public-allowlisted, `Depends(verify_auth)`,
`Depends(optional_verify_auth)`, or inline WS auth. 18 routes are none of those. The
security-relevant subset:

| Route | Concern |
|---|---|
| `GET /api/v1/photos/view/{relative_path:path}` | F-01, unauthenticated arbitrary read |
| `GET /api/v1/devices`, `GET /api/v1/photos/recent` | device + media inventory leak |
| `POST /api/v1/clipboard` | unauthenticated write into shared clipboard state |
| `GET/POST /api/v1/settings`, `/settings/validate-path` | unauthenticated reconfigure of storage root, filesystem probing |
| `POST /api/v1/drop/upload`, `DELETE /api/v1/drop/{id}` | unauthenticated write / delete |
| `GET /api/v1/transfer/list`, `/download-file/{name}`, `/download-folder/{name}` | unauthenticated read of transferred data |

Note the pattern: `optional_verify_auth` on the LANSync endpoints means a *valid* token
is accepted but a missing one is not rejected, so those routes are open to anyone. That
was plausibly deliberate for desktop UX, but it is not documented in an allowlist
comment, which is what the invariant requires.

## 4. Rejected Findings (checker false positives)

Recording these so a future audit does not re-raise them:

- **F-02 — traversal via `/api/v1/drop/download/{file_id}`.** Not reproducible. The
  handler passes `file_id` into `drop_dir.glob(f"{file_id}_*")` (`storage.py:173`), and
  `glob` does not perform path joining, so `..` cannot escape the directory. Safe by
  construction, though it does allow pattern characters; worth a length/charset bound,
  not a traversal fix.
- **F-05 (first draft) — `broadcast_to_ui` mutating `self.ui_connections` mid-iteration.**
  Not reproducible. `websocket_manager.py:78-84` accumulates into `dead_connections`
  during the loop and discards **after** it, which is correct. My initial rule flagged any
  bare `self.ui_connections` iteration; I narrowed it to "mutation inside the loop body"
  so it now passes and still catches the real hazard.

## 8. Recommended Fix Order

1. **F-01 (TD-005)** — one-line containment check, closes an unauthenticated arbitrary
   file read. Do this first.
2. **TD-001** — PIN rate-limit. Brute-forceable pairing is the auth root of trust; F-06's
   impact scales with it.
3. **F-06 (TD-008)** — split the 18 routes into a documented allowlist and authed set.
   Needs a product decision on whether the dashboard routes are LAN-public by design.
4. **F-03 / F-04 (TD-006 / TD-007)** — mechanical, copy the `save_media` staging pattern.
5. **SRP (TD-009)** — extract the 9 Pydantic models into `server/schemas.py`. Cosmetic,
   no security impact.

No desktop (`npm start`) or Android (`gradle assembleDebug`) verification was run: this
audit changed no server behaviour and touched neither client.
